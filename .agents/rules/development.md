# Development Rules

## Understand Before Modifying
- Read and understand the existing code before making any changes.
- Search for existing implementations before creating new files or functions.
- Reuse existing utilities, helpers, and patterns wherever possible.
- Do not modify files unrelated to the current task.

## Implementation
- Make the smallest change necessary to complete the task.
- Match the project's existing coding style, patterns, and architecture.
- Handle errors and edge cases explicitly — do not silently swallow errors.
- Do not introduce unnecessary dependencies or libraries.
- Do not leave dead code, commented-out blocks, or debug statements behind.

## File and Naming Conventions
- Place new files in the correct existing directory based on the project structure.
- Follow the project's existing naming conventions for files, functions, and variables.
- Do not create duplicate files or redundant helper functions.
- Do not reorganize or rename existing files unless the task explicitly requires it.

## Security
- Never hardcode passwords, API keys, tokens, or secrets.
- Validate and sanitize all user input before use.
- Do not expose sensitive data in logs, error messages, or API responses.
- Follow the project's existing authentication and authorization patterns.
